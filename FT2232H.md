# RP2350B HSTX + FT2232H High-Speed USB Transfer

*Context: pic0rick's RP2040 uses USB Full Speed (12 Mbit/s, practical ~1 MB/s). For 65 Msps × 10-bit raw RF at 200 Hz PRF, the raw data rate is 3.2 MB/s — beyond USB FS. This document describes a high-throughput path using the RP2350B's HSTX peripheral and an FT2232H USB bridge, achieving sustained ~40 MB/s.*

---

## Why: the USB FS bottleneck

| Data type | Rate at 200 Hz PRF | USB FS headroom |
|-----------|-------------------|-----------------|
| Raw RF (65 Msps × 10-bit, 8000 smp/acq) | 3.2 MB/s | Marginally fits (80% of ceiling) |
| Raw RF at 400 Hz PRF | 6.4 MB/s | **Exceeds USB FS** |
| 2× decimated RF | 1.6 MB/s | Fits comfortably |
| Envelope only (uint16) | 0.8 MB/s | Fits easily |

At 400 Hz PRF (needed for faster heartbeat tracking or high-PRF Doppler), raw RF cannot be streamed over USB Full Speed. The FT2232H bridge resolves this by adding a USB High Speed (480 Mbit/s) path without changing the RP2350's core USB controller, which remains Full Speed only.

RP2350B adds the HSTX peripheral — a high-speed parallel output capable of driving 8 data lines at up to 300 Mbit/s per line. Combined with an FT2232H in synchronous FIFO mode (245 mode), this creates a 40–60 MB/s data path to the host.

---

## Hardware connections

### FT2232H overview

The FT2232H is a dual-channel USB 2.0 Hi-Speed (480 Mbit/s) UART/FIFO/MPSSE bridge. Channel A in **synchronous 245 FIFO mode** acts as a parallel FIFO: the host writes/reads 8-bit words, synchronised to a 60 MHz clock the FT2232H generates internally.

FTDI provides two breakout options relevant here:
- **Digilent HS2 / FTDI C232HM cable**: USB-C with FT232H (single channel variant); simpler for initial bringup
- **FT2232H mini-module (Mouser/Digikey, ~€12)**: dual-channel, channel B available for UART debug

### Pin mapping

**FT2232H Channel A — Synchronous 245 FIFO mode pins:**

| FT2232H pin | Signal | Direction | RP2350B GPIO | Notes |
|-------------|--------|-----------|--------------|-------|
| ADBUS0–7 | Data[0:7] | MCU→FTDI (write) | GPIO 12–19 (HSTX DATA) | Bidirectional for reads; tie OE# low for pure TX |
| ACBUS0 (RXF#) | FIFO not empty | FTDI→MCU | GPIO 20 | Active low. Monitor for host→device data (not needed for pure TX) |
| ACBUS1 (TXE#) | TX FIFO not full | FTDI→MCU | GPIO 21 | Active low. MCU must NOT write when high |
| ACBUS2 (RD#) | Read strobe | MCU→FTDI | GPIO 22 (tie high if TX-only) | Pull high (disable reads) for pure transmit |
| ACBUS3 (WR) | Write strobe | MCU→FTDI | GPIO 23 or PIO-driven | Active high in sync mode. Assert with each data byte |
| ACBUS4 (CLKOUT) | 60 MHz clock from FTDI | FTDI→MCU | GPIO 24 (input) | **FT2232H is the clock master in sync FIFO mode** |
| ACBUS5 (OE#) | Bus direction | MCU→FTDI | Tie low (MCU always drives data) | Pull to GND for pure TX |
| ACBUS7 (PWRSAV#) | Power save | MCU→FTDI | Tie high (disable power save) | |

**Voltage levels:**
- FT2232H VCCIO pin sets the I/O voltage. Connect VCCIO to 3.3V for direct compatibility with RP2350B GPIO (3.3V logic).
- No level shifting required when VCCIO = 3.3V.
- FT2232H VCC (core): 3.3V (may use internal LDO from USB 5V; verify with mini-module schematic).
- USB VBUS (5V) feeds FT2232H separately.

**Series termination:** Add 33Ω series resistors on ADBUS0–7 lines at the RP2350B end. At 60 MHz with PCB trace lengths > 5 cm, this damps reflections at the FT2232H receiver. Omit for short traces (< 3 cm).

## HSTX configuration

### Key constraint: HSTX is MCU-clocked, FT2232H sync FIFO is FTDI-clocked

In synchronous 245 FIFO mode, the FT2232H drives a 60 MHz CLKOUT. The MCU is expected to synchronise its writes to this clock. HSTX generates its own clock and does not accept an external clock input — this creates a fundamental mismatch.

**Three implementation options, in order of practicality:**

### Option A: PIO state machine (recommended)

Use a RP2350B PIO state machine to implement the full synchronous FIFO write protocol. PIO can monitor TXE# and synchronise to CLKOUT:

```
; PIO program: synchronous FIFO write to FT2232H
; Runs at 4× CLKOUT (240 MHz PIO clock for 60 MHz CLKOUT)
; GPIO mapping: OUT pins = ADBUS[7:0], side-set pin = WR
.program ft2232h_sync_fifo
.side_set 1                 ; WR signal on side-set pin

.wrap_target
    ; Wait for rising edge of CLKOUT (pin 24)
    wait 0 gpio 24          ; wait for CLKOUT low
    wait 1 gpio 24          ; wait for CLKOUT rising edge

    ; Check TXE# (GPIO 21): if high, FTDI TX FIFO is full — loop
    jmp pin write_byte      ; if TXE# is low (GPIO 21 = 0), can write

    ; TXE# high: skip this cycle, do not write
    jmp .wrap_target        side 0

write_byte:
    ; Pull next byte from FIFO (stall if empty)
    pull block              side 0
    ; Drive data onto ADBUS lines, assert WR
    out pins, 8             side 1  ; output 8 bits, WR high
    ; WR pulse lasts one CLKOUT cycle
    nop                     side 0  ; WR low on next cycle
.wrap
```

PIO clock: set to 240 MHz (RP2350B system clock) or 4× CLKOUT. The state machine runs 4 instructions per CLKOUT cycle, allowing TXE# polling each cycle.

**Throughput:** At 60 MHz CLKOUT with TXE# idle-low (FIFO not full): 60 Mbytes/s theoretical. FT2232H USB HS bandwidth: ~40 MB/s sustained. PIO approach matches FT2232H's throughput without the clock-synchronisation complexity of HSTX.

### Option B: HSTX as raw data blaster (async, no flow control)

Configure HSTX to run at ~60 MHz (set via PLL), driving ADBUS0–7. WR is asserted permanently (tied high). TXE# monitoring is done via interrupt on GPIO 21 — when TXE# goes high (FTDI full), pause DMA; when it goes low, resume.

```c
// HSTX configuration for 8-bit parallel output
void hstx_init_8bit(uint clk_mhz) {
    // HSTX uses GPIOs 12-19 (DATA[0:7])
    for (int i = 0; i < 8; i++) {
        gpio_set_function(12 + i, GPIO_FUNC_HSTX);
    }

    // Configure HSTX: 8-bit command expansion, raw FIFO mode
    hstx_ctrl_hw->csr = (1 << HSTX_CTRL_CSR_EN_LSB)    |  // enable
                        (7 << HSTX_CTRL_CSR_EXPAND_N_LSB) | // 8 bits per word
                        (0 << HSTX_CTRL_CSR_CLKDIV_LSB);    // clock divider

    // Set HSTX clock to target MHz via PLL configuration
    // (RP2350 PLL setup; refer to hardware/clocks.h in Pico SDK)
}

// DMA channel: feeds HSTX FIFO from ADC buffer
void dma_to_hstx_init(void) {
    int ch = dma_claim_unused_channel(true);
    dma_channel_config cfg = dma_channel_get_default_config(ch);
    channel_config_set_transfer_data_size(&cfg, DMA_SIZE_8);
    channel_config_set_dreq(&cfg, DREQ_HSTX);  // pace by HSTX FIFO level
    channel_config_set_read_increment(&cfg, true);
    channel_config_set_write_increment(&cfg, false);
    dma_channel_configure(ch, &cfg,
        &hstx_fifo_hw->port,  // write to HSTX FIFO
        adc_buf,               // read from ADC DMA buffer
        buf_len,
        false                  // don't start yet
    );
}
```

**Limitation:** HSTX clock and FT2232H CLKOUT are independent oscillators (~±50 ppm each). At 60 MHz over long transfers, this causes data byte alignment drift. For short bursts (< 1 ms at 60 MB/s = 60,000 bytes), drift is negligible. For sustained streaming, the PIO approach (Option A) is more reliable.

### Option C: Feedback loop using HSTX + CLKOUT input

Route FT2232H CLKOUT into RP2350B and use it to gate the HSTX DMA via a PIO intermediate. Complex; not recommended. Option A achieves the same result more simply.

## FT2232H configuration: synchronous 245 FIFO mode

### Device configuration (one-time, using FT_Prog or OpenOCD/FTProg)

1. In FT_Prog (Windows) or `ftdi_eeprom` (Linux): set Channel A to **"245 FIFO"** mode (not UART, not MPSSE).
2. Set **Interface A** = FT245 Asynchronous or Synchronous FIFO. For maximum throughput, select **Synchronous FIFO**.
3. The FT2232H automatically drives ACBUS4 (CLKOUT) at 60 MHz in synchronous mode.
4. Save configuration to the FT2232H's EEPROM.

### Synchronous FIFO write protocol (MCU perspective)

On each rising edge of CLKOUT:
1. Sample TXE# (ACBUS1). If high (FIFO full): hold current data, do not toggle WR.
2. If TXE# is low (FIFO not full): place data on ADBUS[7:0], assert WR high.
3. FT2232H latches data on the next rising edge of CLKOUT.
4. De-assert WR on the following clock.

Minimum WR pulse width: 1 CLKOUT cycle = 16.67 ns. Minimum data setup before WR rising edge: 5 ns (from FT2232H datasheet, VCCIO = 3.3V).

## Host-side software

### Option A: libftdi (open source, Linux/macOS/Windows)

```python
import ftdi1 as ftdi
import numpy as np

ctx = ftdi.new()
ftdi.usb_open(ctx, 0x0403, 0x6010)          # FT2232H VID/PID
ftdi.set_interface(ctx, ftdi.INTERFACE_A)
ftdi.set_bitmode(ctx, 0xFF, ftdi.BITMODE_SYNCFF)  # 245 sync FIFO

buf = np.zeros(65536, dtype=np.uint8)
ret, nread = ftdi.read_data(ctx, buf, len(buf))
# nread = number of bytes received
# buf[:nread] = raw data from MCU
```

`libftdi` is MIT-licensed, works on Linux without Zadig driver install. Throughput with `ftdi.read_data` in a tight loop: ~35–40 MB/s.

### Option B: D2XX (proprietary, FTDI's official driver)

```python
import ftd2xx as ft

dev = ft.open(0)
dev.setBitMode(0xFF, 0x40)  # 0x40 = sync FIFO
dev.setTimeouts(1000, 1000)
data = dev.read(65536)
```

D2XX achieves slightly higher throughput (~45 MB/s) and has official FTDI support. Requires the D2XX driver installed; conflicts with OS CDC/UART driver on Windows without Zadig.

### Recommended: libftdi + asyncio

For a Python host that mirrors the existing `pic0lib` interface, use `libftdi` with a background thread reading from the FT2232H and depositing frames into a queue that the main thread consumes.

## Realistic throughput and bottlenecks

| Stage | Ceiling | Notes |
|-------|---------|-------|
| HSTX or PIO output | 60 MB/s | FT2232H CLKOUT limit |
| FT2232H TX FIFO to USB | ~40 MB/s | USB 2.0 HS overhead (~17%) |
| USB HS bus | 480 Mbit/s = 60 MB/s | Theoretical |
| libftdi host read | ~35–40 MB/s | Python/libftdi overhead |
| D2XX host read | ~40–45 MB/s | |
| **Practical sustained** | **~40 MB/s** | FT2232H is the bottleneck |

**Comparison with pic0rick baselines:**

| Path | Throughput | Data at 200 Hz PRF | Fits? |
|------|-----------|-------------------|-------|
| USB Full Speed (current Pico) | ~1 MB/s | 3.2 MB/s raw RF | No (need 4× decimation) |
| FT2232H sync FIFO | ~40 MB/s | 3.2 MB/s raw RF | Yes (12× headroom) |
| FT2232H sync FIFO | ~40 MB/s | 6.4 MB/s at 400 Hz PRF | Yes (6× headroom) |
| FT2232H sync FIFO | ~40 MB/s | Raw RF at 65 Msps | No (81 MB/s > 40 MB/s) |

**Bottom line:** The FT2232H resolves the USB bottleneck for all practical PRF rates at 65 Msps. Raw continuous streaming at full 65 Msps with no on-chip reduction is still not achievable (81 MB/s > 40 MB/s limit), but 2× decimation (32.5 MB/s effective) fits comfortably.
