# CH569 + RP2350B: USB 3.0 SuperSpeed Data Exfiltration

*Context: The FT2232H (see `FT2232H.md`) solves the USB Full Speed bottleneck and gives ~40 MB/s over USB 2.0 HS. The CH569 (WCH RISC-V, native USB 3.0 SuperSpeed) pushes this to ~300–400 MB/s while simultaneously exposing a CDC-ACM serial port — all through a single USB-C connector, with no proprietary driver on the host side.*

---

## When to use CH569 vs FT2232H

| Scenario | FT2232H | CH569 |
|----------|---------|-------|
| Raw RF at 200 Hz PRF (3.2 MB/s) | ✓ 12× headroom | Overkill |
| Raw RF at 400 Hz PRF (6.4 MB/s) | ✓ 6× headroom | Overkill |
| Full 65 Msps uncompressed (~80 MB/s) | ✗ Exceeds ceiling | ✓ |
| CDC-ACM serial + data on one cable | ✗ Needs second channel | ✓ composite |
| Linux host, no custom driver | Needs libftdi install | ✓ Standard bulk + CDC |
| BOM delta | ~€12 module / €5 IC | ~€3–5 IC (LQFP-64) |
| SDK / toolchain complexity | Simple (libftdi) | High (WCH RISC-V toolchain) |

For ultr4rick at 200 Hz PRF, FT2232H is the right answer. CH569 is the path when full-rate uncompressed streaming, combined host composite device (data + serial in one descriptor), or driver-free Linux deployment is required.

## Hardware Interface: RP2350B ↔ CH569

### Bus selection

| Bus option | Speed | Pros | Cons |
|-----------|-------|------|------|
| **CH569 HSPI slave (SPI-compatible)** | Up to ~60 MHz | Native CH569 DMA peripheral; direct RP2350B SPI | Unidirectional data; HSPI_ACK needed for flow control |
| Parallel 8-bit (FT245-style) | ~480 MB/s | Maximum throughput | CH569 has no parallel slave mode; needs CPLD |
| UART | 12 Mbps max | Trivial wiring | Far too slow for bulk data |

**HSPI slave is the correct interface.** At 60 MHz × 8 bits = 60 MB/s sustained — well above the 3.2–80 MB/s use cases. RP2350B drives it via either the native SPI peripheral (≤ 37.5 MHz at 150 MHz system clock) or a PIO state machine (60 MHz achievable).

### Pin mapping

| Signal | RP2350B GPIO | CH569 Pin | Direction | Notes |
|--------|-------------|-----------|-----------|-------|
| HSPI_CK | GPIO 10 | PA14 (HSPI_CK) | RP→CH | SPI clock, mode 0 (CPOL=0, CPHA=0) |
| HSPI_MOSI | GPIO 11 | PA13 (HSPI_RX) | RP→CH | Data from RP2350B to CH569 |
| HSPI_CS | GPIO 12 | PA12 (HSPI_CS) | RP→CH | Active low; assert before burst |
| HSPI_ACK | GPIO 13 (input) | PA15 (HSPI_ACK) | CH→RP | CH569 asserts when ready for next block |
| RESET# | GPIO 14 (output) | NRST | RP→CH | Optional; pull high normally |

**Voltage:** RP2350B and CH569 both operate at 3.3V I/O. No level shifting required.

**Series termination:** 33Ω on CK and MOSI at RP2350B end for PCB traces > 5 cm.

**CH569 crystal:** USB 3.0 requires precise clock. CH569 needs a 30 MHz external crystal on XI/XO pins (or 25 MHz depending on variant — verify against CH569 datasheet). The internal RC oscillator is not adequate for USB3.

## Firmware Split

| Responsibility | Runs on | Mechanism |
|---------------|---------|-----------|
| ADC capture, ping-pong DMA | RP2350B Core 0 | SPI DMA, interrupt on complete |
| Hilbert / envelope (optional) | RP2350B Core 1 | CMSIS-DSP (see `M33FPUHILBERT.md`) |
| Push 16 KB block to CH569 | RP2350B SPI master | DMA → SPI TX FIFO; wait HSPI_ACK high |
| Receive block from RP2350B | CH569 HSPI slave | HSPI DMA → SRAM ping-pong |
| USB3 bulk IN to host | CH569 USB3 controller | DMA from SRAM, EP4, 1024 B packets |
| USB3 CDC-ACM serial | CH569 USB3 controller | EP1/EP2 bulk + EP3 interrupt |
| USB enumeration / EP0 | CH569 USB3 stack | Class request handler in firmware |

RP2350B is not aware of USB at all — it pushes data over SPI and waits for ACK. The CH569 handles everything USB-facing.

### 1. USB3 composite descriptor

The device enumerates as a composite device using IAD. Three interfaces:
- **Interface 0:** CDC communication (control, notification EP3 interrupt IN)
- **Interface 1:** CDC data (EP1 bulk OUT + EP2 bulk IN)
- **Interface 2:** Vendor bulk data (EP4 bulk IN — 16 KB frames from RP2350B)

SuperSpeed requires a BOS descriptor and a SuperSpeed Endpoint Companion Descriptor after each non-zero endpoint descriptor.

#### Device descriptor

```c
const uint8_t USB3_DeviceDescriptor[18] = {
    0x12,        /* bLength */
    0x01,        /* bDescriptorType: Device */
    0x00, 0x03,  /* bcdUSB: 3.00 */
    0xEF,        /* bDeviceClass: Miscellaneous — required for IAD composite */
    0x02,        /* bDeviceSubClass */
    0x01,        /* bDeviceProtocol: IAD */
    0x09,        /* bMaxPacketSize0: 2^9 = 512 B (SS control EP; coded as exponent) */
    0x86, 0x1A,  /* idVendor: 0x1A86 WCH — change for production */
    0x69, 0x55,  /* idProduct: 0x5569 — assign per project */
    0x00, 0x01,  /* bcdDevice: 1.00 */
    0x01,        /* iManufacturer */
    0x02,        /* iProduct */
    0x00,        /* iSerialNumber */
    0x01,        /* bNumConfigurations */
};
```

#### BOS descriptor (required for SuperSpeed)

```c
const uint8_t USB3_BOSDescriptor[22] = {
```

#### Configuration descriptor (115 bytes, all interfaces and SS companion descriptors)

```c
/*
 * Layout (115 bytes):
 *   Config(9) + IAD(8)
 *   + If0 CDC comm(9) + CDC FDs(5+5+4+5) + EP3 intr(7) + EP3 SSC(6)
 *   + If1 CDC data(9) + EP1 OUT(7) + EP1 SSC(6) + EP2 IN(7) + EP2 SSC(6)
 *   + If2 vendor(9) + EP4 IN(7) + EP4 SSC(6)
 *   = 17 + 41 + 35 + 22 = 115
 */
#define CFG_DESC_LEN  115

const uint8_t USB3_ConfigDescriptor[CFG_DESC_LEN] = {
    /* Configuration Descriptor */
    0x09, 0x02, 0x73, 0x00,   /* wTotalLength = 115 = 0x73 */
    0x03,                      /* bNumInterfaces: 3 */
    0x01, 0x00, 0x80, 0xFA,   /* bConfigVal, iConfig, bmAttr bus-pwr, bMaxPower 500mA */

    /* IAD: bind interfaces 0–1 as CDC-ACM */
    0x08, 0x0B, 0x00, 0x02, 0x02, 0x02, 0x01, 0x00,

    /* Interface 0: CDC Communication */
    0x09, 0x04, 0x00, 0x00, 0x01, 0x02, 0x02, 0x01, 0x00,
    /* CDC Header FD */
    0x05, 0x24, 0x00, 0x10, 0x01,
    /* CDC Call Management FD (no call mgmt, data on If1) */
    0x05, 0x24, 0x01, 0x00, 0x01,
    /* CDC ACM FD (line coding + control state) */
    0x04, 0x24, 0x02, 0x02,
    /* CDC Union FD (master=If0, slave=If1) */
    0x05, 0x24, 0x06, 0x00, 0x01,
    /* EP3 IN Interrupt: CDC notification, 64 B, 10 ms */
    0x07, 0x05, 0x83, 0x03, 0x40, 0x00, 0x0A,
    /* EP3 SS Endpoint Companion */
    0x06, 0x30, 0x00, 0x00, 0x40, 0x00,  /* wBytesPerInterval=64 for interrupt */

    /* Interface 1: CDC Data */
    0x09, 0x04, 0x01, 0x00, 0x02, 0x0A, 0x00, 0x00, 0x00,
    /* EP1 Bulk OUT: CDC data host→device, 1024 B SS max packet */
    0x07, 0x05, 0x01, 0x02, 0x00, 0x04, 0x00,
    /* EP1 SS Endpoint Companion */
    0x06, 0x30, 0x00, 0x00, 0x00, 0x00,
    /* EP2 Bulk IN: CDC data device→host */
    0x07, 0x05, 0x82, 0x02, 0x00, 0x04, 0x00,
    /* EP2 SS Endpoint Companion */
    0x06, 0x30, 0x00, 0x00, 0x00, 0x00,

    /* Interface 2: Vendor bulk (data exfiltration) */
    0x09, 0x04, 0x02, 0x00, 0x01, 0xFF, 0x00, 0x00, 0x00,
    /* EP4 Bulk IN: 16 KB frames to host */
    0x07, 0x05, 0x84, 0x02, 0x00, 0x04, 0x00,
    /* EP4 SS Endpoint Companion (bMaxBurst=15: 16 packets × 1024 B = 16 KB per burst) */
    0x06, 0x30, 0x0F, 0x00, 0x00, 0x00,
};
```

`bMaxBurst = 0x0F` on EP4 tells the host it can batch up to 16 × 1024 B = 16 KB per burst, exactly matching the acquisition packet size. Set to `0x00` to revert to single-packet mode if the host has compatibility issues.

### 2. HSPI slave initialisation and ISR

```c
#include "CH56x_common.h"

#define PKT_SIZE    (8192u * 2u)   /* 16 KB per acquisition packet */

/* Ping-pong SRAM buffers; 4-byte aligned for DMA */
static __attribute__((aligned(4))) uint8_t hspi_buf[2][PKT_SIZE];
static volatile uint8_t hspi_fill_idx = 0;  /* buffer HSPI is writing into */
static volatile uint8_t pkt_ready     = 0;  /* set by ISR, cleared by main loop */
static volatile uint8_t pkt_ready_idx = 0;  /* which buffer is ready for USB3 TX */

void HSPI_Slave_Init(void) {
    /* Enable HSPI peripheral clock (SDK macro; may be SYS_ClockCmd or similar) */
    RCC_HSPI_ENABLE();

    /*
     * CFG: slave mode (RB_HSPI_MODE = 0), MSB first, DMA enabled.
     * CH569 HSPI default is SPI mode 0 (CPOL=0, CPHA=0).
     */
    R8_HSPI_CFG = RB_HSPI_MSB_FIRST | RB_HSPI_DMA_EN;

    /* Point DMA at buffer 0 for the first receive */
    R32_HSPI_RX_ADDR = (uint32_t)hspi_buf[0];
    R16_HSPI_DMA_LEN = PKT_SIZE;

    /* Clear pending flags, then enable RX-done and FIFO-overflow interrupts */
    R8_HSPI_INT_FLAG = RB_HSPI_IF_R_DONE | RB_HSPI_IF_FIFO_OV;
    R8_HSPI_INT_EN   = RB_HSPI_IE_R_DONE | RB_HSPI_IE_FIFO_OV;

    /* Enable HSPI in slave mode */
    R8_HSPI_CFG |= RB_HSPI_ENABLE;

    PFIC_EnableIRQ(HSPI_IRQn);
}

/*
 * HSPI ISR — fires when PKT_SIZE bytes have been received from RP2350B.
 * Swaps DMA to the alternate buffer (zero dead time) and signals the main loop.
 */
__attribute__((interrupt("WCH-Interrupt-fast")))
void HSPI_IRQHandler(void) {
    if (R8_HSPI_INT_FLAG & RB_HSPI_IF_FIFO_OV) {
        R8_HSPI_INT_FLAG = RB_HSPI_IF_FIFO_OV;
        /* FIFO overflow: RP2350B clocked too fast or ACK was not honoured */
    }

    if (R8_HSPI_INT_FLAG & RB_HSPI_IF_R_DONE) {
        R8_HSPI_INT_FLAG = RB_HSPI_IF_R_DONE;

        /* Record which buffer just filled, swap to the other */
        pkt_ready_idx       = hspi_fill_idx;
        hspi_fill_idx       = 1u - hspi_fill_idx;

        /* Re-arm DMA on the now-empty buffer */
        R32_HSPI_RX_ADDR = (uint32_t)hspi_buf[hspi_fill_idx];
        R16_HSPI_DMA_LEN = PKT_SIZE;

        /* Assert HSPI_ACK to release RP2350B for the next transfer */
        /* ACK is a GPIO toggled by firmware; exact mechanism is board-specific */
        GPIO_SetBits(HSPI_ACK_PORT, HSPI_ACK_PIN);

        pkt_ready = 1;
    }
}
```

### 3. USB3 bulk IN endpoint handler (EP4)

```c
/*
 * Send one 16 KB packet over USB3 EP4 bulk IN.
 *
 * The USB3 SS controller packetises automatically into 1024-byte bulk packets.
 * With bMaxBurst=15 on EP4, the host will accept all 16 packets in one burst.
 *
 * Register names follow WCH CH569 TRM (USBSS peripheral, endpoint 4).
 * Verify UEP4_TX_DMA / UEP4_TX_LEN / UEP4_TX_CTRL names against your EVT SDK.
 */
void USB3_EP4_BulkIN_Send(const uint8_t *buf, uint16_t len) {
    /* Spin until EP4 TX is not busy (previous transfer complete) */
    while (USBSS->UEP4_TX_CTRL & UEP_T_RES_BUSY);

    USBSS->UEP4_TX_DMA  = (uint32_t)buf;
    USBSS->UEP4_TX_LEN  = len;                          /* 16384 bytes */
    USBSS->UEP4_TX_CTRL = UEP_T_RES_ACK | UEP_T_AUTO_TOG;  /* arm TX */
}

/*
 * Main loop: drain the HSPI→USB3 pipeline.
 * Called from main() after USB3 enumeration completes and host opens EP4.
 */
void DataPipeline_Run(void) {
    while (1) {
        if (pkt_ready) {
            pkt_ready = 0;
            USB3_EP4_BulkIN_Send(hspi_buf[pkt_ready_idx], PKT_SIZE);
        }
    }
}
```

### 4. CDC-ACM endpoints (EP1 / EP2 / EP3)

CDC-ACM on a USB3 SS device is functionally identical to USB2 CDC-ACM — the class requests and data format are the same; only the endpoint descriptors and companion descriptors differ. The device must handle three EP0 class requests:

```c
typedef struct __attribute__((packed)) {
    uint32_t dwDTERate;    /* baud rate (e.g. 115200) */
    uint8_t  bCharFormat;  /* stop bits: 0=1, 1=1.5, 2=2 */
    uint8_t  bParityType;  /* 0=None, 1=Odd, 2=Even */
    uint8_t  bDataBits;    /* 5, 6, 7, 8, or 16 */
} CDC_LineCoding;

static CDC_LineCoding line_coding = { 115200, 0, 0, 8 };

/*
 * EP0 class request handler for Interface 0 (CDC communication).
 * Called from the USB3 stack's SETUP packet handler when bmRequestType
 * indicates class + interface and wIndex == 0.
 */
void CDC_ClassRequest_Handler(USB_SETUP_REQ *req, uint8_t **data_out, uint16_t *len_out) {
    switch (req->bRequest) {
    case CDC_SET_LINE_CODING:
        /* Host sends 7-byte line coding struct; copy on DATA stage */
        /* WCH stack calls this again with the data; update line_coding there */
        *len_out = 0;
        break;

    case CDC_GET_LINE_CODING:
        *data_out = (uint8_t *)&line_coding;
        *len_out  = sizeof(line_coding);
        break;

    case CDC_SET_CONTROL_LINE_STATE:
        /* wValue bit 0 = DTR, bit 1 = RTS; can gate EP4 TX on DTR if desired */
        *len_out = 0;
        break;

    default:
        /* Stall unknown class requests */
        USBSS->UEP0_TX_CTRL = UEP_T_RES_STALL;
        return;
    }
}

/*
 * CDC TX (device→host): write a string to EP2 bulk IN.
 * Use for debug output — identical in interface to a UART write.
 */
void CDC_SendString(const char *s) {
    uint16_t len = (uint16_t)strlen(s);
    while (USBSS->UEP2_TX_CTRL & UEP_T_RES_BUSY);
    memcpy(cdc_tx_buf, s, len);
    USBSS->UEP2_TX_DMA  = (uint32_t)cdc_tx_buf;
    USBSS->UEP2_TX_LEN  = len;
    USBSS->UEP2_TX_CTRL = UEP_T_RES_ACK | UEP_T_AUTO_TOG;
}
```

EP3 (interrupt IN, CDC notification) only needs to send a `SERIAL_STATE` notification when the control line state changes. For a data-only application, it can stay armed with length 0 and never fire.

### 5. Main initialisation outline

```c
int main(void) {
    /* System clock: configure for 120 MHz from 30 MHz crystal */
    SystemInit();          /* WCH SDK: sets PLL, flash wait states */

    /* Peripheral init */
    HSPI_Slave_Init();     /* HSPI slave DMA, ISR */
    USB3_DeviceInit();     /* WCH SDK: enumerate, register descriptor pointers */

    /* Register descriptors with the USB3 stack */
    USB3_SetDeviceDescriptor(USB3_DeviceDescriptor, sizeof(USB3_DeviceDescriptor));
    USB3_SetBOSDescriptor(USB3_BOSDescriptor, sizeof(USB3_BOSDescriptor));
    USB3_SetConfigDescriptor(USB3_ConfigDescriptor, sizeof(USB3_ConfigDescriptor));
    /* Register string descriptors (manufacturer, product) similarly */

    /* Wait for host to enumerate and open EP4 before starting pipeline */
    while (!USB3_IsConfigured());

    CDC_SendString("CH569 ready\r\n");

    /* Main data loop */
    DataPipeline_Run();    /* never returns */
}
```

## RP2350B Side (SPI Master)

The RP2350B needs only a standard SPI master pushing 16 KB blocks, with a GPIO check on HSPI_ACK before each transfer.

```c
#include "hardware/spi.h"
#include "hardware/dma.h"

#define SPI_INST        spi1
#define SPI_CLK_HZ      30000000   /* 30 MHz; raise to 60 MHz after validation */
#define SPI_MOSI_PIN    11
#define SPI_CLK_PIN     10
#define SPI_CS_PIN      12
#define HSPI_ACK_PIN    13

void ch569_spi_init(void) {
    spi_init(SPI_INST, SPI_CLK_HZ);
    spi_set_format(SPI_INST, 8, SPI_CPOL_0, SPI_CPHA_0, SPI_MSB_FIRST);
    gpio_set_function(SPI_CLK_PIN,  GPIO_FUNC_SPI);
    gpio_set_function(SPI_MOSI_PIN, GPIO_FUNC_SPI);
    gpio_init(SPI_CS_PIN);
    gpio_set_dir(SPI_CS_PIN, GPIO_OUT);
    gpio_put(SPI_CS_PIN, 1);  /* deassert */
    gpio_init(HSPI_ACK_PIN);
    gpio_set_dir(HSPI_ACK_PIN, GPIO_IN);
}

/*
 * Push one 16 KB block to CH569.
 * Called after ADC DMA completes; buf is the completed ping-pong buffer.
 */
void ch569_send_block(const uint8_t *buf, size_t len) {
    /* Wait for CH569 to assert ACK (ready for next packet) */
    while (!gpio_get(HSPI_ACK_PIN));

    gpio_put(SPI_CS_PIN, 0);                        /* assert CS */
    spi_write_blocking(SPI_INST, buf, len);          /* DMA variant preferred */
    gpio_put(SPI_CS_PIN, 1);                        /* deassert CS */
}
```

For production: replace `spi_write_blocking` with a DMA transfer to the SPI TX FIFO so Core 0 is free to set up the next ADC acquisition while the SPI DMA runs in the background.

## Host Side

CH569's composite device uses standard OS drivers — no libftdi, no D2XX, no Zadig:

```python
import usb.core, usb.util
import serial                  # pyserial for CDC-ACM

# Bulk data endpoint (Interface 2, EP4 IN = 0x84)
dev = usb.core.find(idVendor=0x1A86, idProduct=0x5569)
dev.set_configuration()
ep_data = dev[0][(2, 0)][0]   # Interface 2, alternate 0, endpoint 0

while True:
    data = dev.read(0x84, 16384, timeout=1000)  # 16 KB per read
    # data is numpy-convertible: np.frombuffer(data, dtype=np.uint16)

# Serial port opens as /dev/ttyACM0 (Linux) or COMx (Windows) automatically
ser = serial.Serial('/dev/ttyACM0', 115200)
ser.write(b'status\r\n')
```

On Linux the kernel's `cdc_acm` module claims Interface 0–1 automatically; Interface 2 (vendor bulk) is left unclaimed for `libusb`. No `udev` rule needed for the bulk endpoint.

## Throughput Analysis

| Stage | Ceiling | Notes |
|-------|---------|-------|
| RP2350B SPI master | 60 MB/s | At 60 MHz × 8 bits |
| CH569 HSPI slave DMA | 60 MB/s | Matches SPI master |
| CH569 SRAM → USB3 DMA | > 200 MB/s | Internal bus, not the bottleneck |
| USB3 SS bulk (EP4, bMaxBurst=15) | ~350–400 MB/s | Practical USB3 bulk ceiling |
| **Bottleneck** | **60 MB/s** | SPI link between RP2350B and CH569 |

The SPI link — not USB3 — is the ceiling. For the ultrasound use case:

| Data type | Rate | Fits 60 MB/s? |
|-----------|------|---------------|
| Raw RF at 200 Hz PRF (8000 smp × 2 B × 200) | 3.2 MB/s | Yes — 18× headroom |
| Raw RF at 400 Hz PRF | 6.4 MB/s | Yes — 9× headroom |
| Full 65 Msps uncompressed (continuous) | ~81 MB/s | **No — exceeds 60 MB/s SPI link** |
| Full 65 Msps with 2× decimation | ~40 MB/s | Yes |

To push past 60 MB/s: implement dual SPI lanes (two RP2350B SPI peripherals interleaved), or redesign the coupling as a parallel 8-bit bus (requires external FPGA or a custom CH569 parallel mode — neither is straightforward).

## SDK and Toolchain Notes

- **Toolchain:** MounRiver Studio (free, WCH's Eclipse-based IDE) or standalone `riscv-none-embed-gcc` with WCH's multilib patches. Standard RISC-V toolchains do not support the `WCH-Interrupt-fast` attribute.
- **EVT package:** Download `CH569EVT.ZIP` from wch.cn. Contains headers, register definitions, USB3 stack examples (`USBSS_*` functions), and HSPI examples.
- **Register name verification:** `R8_HSPI_CFG`, `R32_HSPI_RX_ADDR`, `USBSS->UEP4_TX_DMA` etc. are based on WCH CH569 TRM v1.x and EVT examples. Cross-check against `CH569.h` in the EVT package before building.
- **USB3 stack:** WCH provides a pre-compiled USB3 library (`libUSBSS.a`). The descriptor registration functions (`USB3_SetDeviceDescriptor` etc.) wrap this library. The EVT `USB3Composite` example is the closest reference.
- **Crystal:** CH569 requires a 30 MHz crystal (or 25 MHz on some sub-variants) for USB3 PLL. RC oscillator is USB-disqualifying.
